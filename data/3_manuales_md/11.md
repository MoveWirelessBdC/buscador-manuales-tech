# What’s New in November 2020

## Brand-New Adding Venues

We have reviewed and updated the process of adding Venues to the Platform, which is now visually consistent with the rest of the Platform interface.

We have also moved it to the **Portal Management > Structure** section; it is now located in the Structure upper bar to facilitate managing Venues in Organisations.

To learn more about adding Venues to an Organisations, read the [Creating, Editing and Deleting a Venue](../../user_guide/portal_management/creating_venue.html) chapter in the User Guide.

**Note:** To use the **Venues** feature, you must first have your Organisation set to the **Location** mode.

## New Timeout Option

We have introduced the new type of **Timeout** in the Page Flow nodes - **Hour** - that allows you to specify the exact hour of the day, after which the user’s session would reset.

### How It Works

#### Use Case

A user is given internet access for one hour per day. Until now, Flow nodes allowed you to configure the session reset only to a specified interval, such as 24 hours. So, if the user browsed the internet on November 1, from 7 to 8 PM, then on the following day, November 2, they would have to wait until 7 PM to gain internet access again. But what if they would like to use it earlier?

#### Solution

The **Hour** option enables you to designate an exact hour of the day when internet access resets. You can set up the reset hour to a preferred one, such as midnight or any other, which would allow the user to browse the internet any time on November 2.

To do this, click the **More** option on the desired node, and select **Timeout** from the dropdown menu. Then, in the pop-up box, select **Hour** from the available options, and specify the time in the selector. To confirm your changes, click **Save** in the bottom right corner of the popup-box.

## Data Transfer Limits

We have implemented the new mechanism which controls data transfer used by WiFi users and terminates user sessions when they reach determined limits.

In the process, we have updated the transfer counting per user which now, apart of counting transfers per sessions, is based on the `UserAccountingEvent` events. Data transfers will also be checked when users log in to the network; if it is used up, users will not be able to log in to your WiFi.w

**Note:** To limit data transfers, you should enable the `userAccountTransferLimitsEnabled` property for the desired Organisations by changing its status to `true`.

You can preview data transfers for all user accounts in the **List of User Accounts** table in the **Access Methods > User Accounts** section.

To ensure that data limits are working correctly, we recommend using devices which support transfer limits and configure them accordingly. Devices supported by the Platform include: CISCO, Ruckus controller, Meraki, Ruckus SZ/vSZ/vSCG, Ruckus SCG 3.2-3.4, RUCKUS\_VSCG\_CLOUD, and other.

For more configuration details, see the **Device Configurations** chapter in the User Guide.
