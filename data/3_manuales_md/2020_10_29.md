# Release Version: 20.10.29\_\_stable\_\_0.28.0

### Release Date: 10/29/2020

## New Features

* We have introduced the new **Top Up** option to the **User Accounts** feature which enables you to top up data transfer for user accounts.

  For more information, see the [What’s New in October](../../whats_new/2020/10.html) chapter.
* We have integrated the new type of Access Points - **Arista** - which you can now add to the Platform

## Updates

### Feature Updates

* We have optimised searching through Networks (SSIDs) which significantly decreased the CPU usage

### API Updates

* We have changed the behaviour of the `location/management/multivenue/scheduler` API endpoint responsible for creating RUCKUS multi-venue within an Organisation’s sub-tree.

  As an addition to creating new Venues, for the already existing `RUCKUS_MULTI_VENUE` Venues with the same `locationName` parameter, we have added an **AP synchronisation** which synchronises the list of the Venue APs with the Organisation Devices.

  **Note:** If no RUCKUS Device (Vsz or Cloud) is found in the Organisation, the Organisation’s Venue will be removed.

  Due to this change, we have added two counting fields to the `location/management/multivenue/scheduler/{operationID}` endpoint:  
  - `removed` which is a Venue that has been previously created in the Organisation which Devices do not match  
  - `existing` which is a Venue that has been previously created in the Organisation and its Venue APs can be updated.

  We have also modified the semantics of the `skipped` field which now contains the count of Organisations for which there was no Venue and no matching devices, or the Venue type or `locationName` did not match.

### Other Updates

* We have updated our alerting system so that it informs us more effectively on system-related issues

## Resolved Issues

### Feature Fixes

* In large Organisations, the **User Count over Time** Dashboard chart displayed incorrect numbers; it has been fixed and the chart now displays data as expected

### GUI Fixes

* The autofill in the Phone Number Input component is now displaying correctly and does not cover up other components in a Captive Portal

### System Fixes

* We have fixed the issue where the Location Engine would create an excessive amount of threads and cause the system to fail.
* We have resolved the problem of multiple simultaneous logins for the same user accounts from telco HLR

### API Fixes

* We have fixed problems with the API spec for `/payments/{organizationId}` which now returns the expected client code.

  As part of the resolution, we have added the following API responses and endpoints:

```
* GET /accessMethods/tokenGroups
* GET /accessMethods/tokenGroups/{tokenGroupId}/tokens/
* GET /accessMethods/userAccounts/
* GET /networks/
* GET /payments/{organizationId}
* PUT /organizations/{organizationId}/radiusVendorSpecificSchema

```
